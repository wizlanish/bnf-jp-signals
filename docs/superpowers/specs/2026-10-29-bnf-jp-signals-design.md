# 日股乖离率抄底信号推送：设计文档

日期：2026-10-29
状态：用户已批准（2026-10-29）

## 1. 要做什么，为什么

用户想用 BNF（小手川隆）早期的打法做日股：股价大幅跌破 25 日均线时抄底，持有几天、反弹到一定位置就卖。他没空盯盘，只能早上用手机挂单、上班时偶尔看一眼。

所以要做一个每天两次的手机推送：
- **7:30（开盘前）**：今天哪些股票可以按什么价格买，以及已有持仓什么价格卖。
- **9:30（开盘后）**：开盘就被砸穿买入线的股票；持仓里已经到卖出目标价的股票。

**推送只给价格和时机，不算股数，也不替用户做决定**，买不买、买多少由用户自己定。用户买入或卖出后，会在本地的 Claude Code 里告诉 Claude，由 Claude 更新持仓文件。

## 2. 目标、非目标、反目标

**目标**
- 每个东证交易日 7:30、9:30 准时推送，内容可以直接照着在 券商 App 里下单。
- 所有计算只用推送那一刻已经知道的数据，不偷看未来。
- 持仓每天都有明确的卖出价格和止损时点。

**非目标**
- 不自动下单，也不接券商的交易权限。
- 不算股数，不管仓位。
- 不用实时行情。这个设计用延迟数据就够了。
- 云端任务不接券商 API。

**反目标**（技术上能跑，但出现了就算失败）
- 大盘平静的日子天天推一长串没用的信息，导致用户不再看推送。
- 计算里混入了未来数据，比如用当天收盘价判断当天开盘该不该买。
- 推送的价格和 券商 App 里看到的对不上，比如用了复权价。

## 3. 策略规则（已经回测过的部分）

研究脚本在 `research/` 下，回测结论见第 8 节。

**股票池**：日经 225 当前成分股，名单在 `n225.txt`，格式是"行业|代码 代码 …"，2026-10-29 从日经官网取得。用户不按行业或过去成绩筛选，样本外检验表明这两种筛法都没用。

**乖离率**：bias = 收盘价 ÷ 25 日均线 − 1，均线用收盘价的简单平均。

**个股买入线 T**：这只股票自己历史乖离率的 2% 分位数。
- 历史从 2010-01-01 开始，至少要 500 个交易日，不够的股票不出信号。
- 只用到昨天为止的数据计算。
- T 是负数，比如 -0.10。

**今天的触发价**：今天价格跌到多少，乖离率正好等于 T。
- 公式：P = (1+T)·S24 / (24−T)
- S24 = 最近 24 个交易日的收盘价之和（截至昨天）

**卖出目标价**：乖离率回到 0.4·T 时的价格。
- 公式：P = (1+0.4T)·S24 / (24−0.4T)，每天重算。

**大盘开关**：日经 225 指数昨天收盘的 25 日乖离率。
- ≤ -5%：开关打开
- ≤ -10%：崩盘档

**破线数量（广度）**：225 只里昨天收盘乖离率 ≤ 自己 T 的股票数。回测显示，这个数是比"选哪只"更重要的信号（见第 8 节）。

**持仓与卖出**：
- 买入那天算第 1 天。
- 第 1~5 天里，任何一天收盘价 ≥ 当天的卖出目标价，就在下一个交易日卖。
- 第 5 天收盘还没到目标，就在第 6 天开盘卖。这是止损。

## 4. 两条推送的内容

**推送里的价格一律用未复权的原始价格**，和券商 App 一致。乖离率和分位数的历史计算可以用复权价，但用来算触发价、目标价的 S24 必须用未复权收盘价。

### 4.1 7:30 推送

1. **大盘一行**：日经昨收和 25 日乖离率；开关状态（关闭 / 打开 / 崩盘档）；昨天破线的股票数。

   开关打开时，再附一行历史参考：

   | 同一天破线数 | 胜率 | 平均每笔 |
   |---|---|---|
   | 1~3 只 | 43% | -0.9% |
   | 4~10 只 | 57% | +1.4% |
   | 11~30 只 | 65% | +2.1% |
   | 30 只以上 | 71% | +2.9% |

2. **已破线**（昨天收盘乖离率 ≤ T 的股票）：
   - 每只一行：代码、名称、昨收、乖离率与 T、一手（100 股）金额、下单方式。
   - 下单方式统一是"开盘买"：一手股用寄付市价；ひと株要在 8:03 前下市价单，按开盘价成交。一手金额只用来帮用户判断走一手还是 ひと株，不是在算股数。
   - 按过去 250 天的年化波动率从高到低排序。
   - **开关关闭时**（我的判断）：只写破线数量，并注明"大盘未恐慌，个股单独破线历史上不赚钱"。不展开列表，最多附上代码。

3. **埋伏价**：只在开关打开时出现。
   - 列出还没破线、但昨收在今天触发价上方 5% 以内的股票，给出今天的触发价，供用户挂限价买单。
   - ひと株不能挂限价，所以这一栏注明"一手股适用"。

4. **持仓**：每只一行，写今天的卖出目标价、持有第几天、现在离目标还差多少。
   - 一手股：写"限价卖 XXXX"。
   - ひと株（股数 < 100）：如果昨天收盘已经 ≥ 目标价，或者已经过了第 5 天，写"8:03 前市价卖"；否则写"观望，目标 XXXX"。
   - 一手股如果也满足"昨收到目标"或"过了第 5 天"，就写"开盘市价卖"。

5. **开关关闭、又没有持仓的日子**：整条推送只有大盘那一行，加上"今天不动"。

### 4.2 9:30 推送（只在有事时才发）

用的是 yfinance 的盘中最新价，大约 9:10 的价格（有约 20 分钟延迟）。

- **开盘砸穿**：开关打开时，最新价 ≤ 今天触发价、而且不在昨天已破线名单里的股票。写出现价和触发价。注明：一手股可以马上买；ひと株只能按当天收盘价成交。
- **持仓到价**：今天最高价 ≥ 卖出目标价的持仓，提示"限价单大概已经成交，请确认"。

以上两种情况都没有，就不发。

## 5. 持仓文件

持仓**不进仓库**，因为仓库是公开的；`holdings.json` 写进 `.gitignore`。持仓写在两个云端定时任务的指令里，任务运行时先把它写成 `holdings.json`，再跑脚本。

用户说买了或卖了，Claude 在本地用 RemoteTrigger 更新这两个任务的指令。格式由实现者定，至少要有这些字段：
- 代码
- 股数（< 100 视为 ひと株）
- 买入价
- 买入日期

用户说卖了，就删除那条，或者标记为已卖出。

## 6. 运行方式

- 本地仓库：`~/bnf-jp-signals`。远端是用户 GitHub（wizlanish）下的**公开**仓库，里面只有代码，没有个人数据。
  - 改成公开的原因：用户的 claude.ai 是组织账户，不能连接 GitHub，云端任务拉不了私有仓库。所以改为直接 `git clone` 公开仓库。（2026-10-29 用户选择）
- 一个 Python 脚本，用参数区分 7:30 和 9:30 两种模式，把推送文本输出到 stdout。数据用 yfinance。
- 两个云端定时任务（Claude Code routines），周一到周五 7:30 和 9:30（JST）运行：拉取仓库最新版本，跑脚本，用 PushNotification 把输出推到手机。
  - 用户已有的另一个推送任务就是这样跑的，PushNotification 在云端可用。
  - 云端里 Claude Docs 连接器用不了，所以不要依赖它。
- **还没验证过的前提**：云端任务里能 pip 安装 yfinance、能连上 Yahoo、能下载约 225 只股票的历史数据，也能 `git clone` 公开仓库。那个任务只证明了推送可用，不能证明这些。所以写正式脚本之前，先用一个测试任务把这几件事验证一遍。
  - 如果 Yahoo 在云端被封，或者被限流（我的判断）：先换其他免费数据源；不行的话，改由 GitHub Actions 每天算好结果、提交到仓库，云端任务只负责读结果并推送。
  - 无论哪种方案，都不能依赖用户的 Mac 开着。
- 非东证交易日不推送，包括周末、日本节假日、12/31~1/3。7:30 那次还拿不到当天的数据，所以要靠日历判断。
- 推送长度有限。列表太长时，只保留前若干只，再写上"共 N 只"。具体截断多少由实现者定。

## 7. 开工前必须先做：盘中限价买卖的回测

已有回测的执行方式是"开盘买、开盘卖"。但 4.1 的埋伏价（限价买）和一手股的限价卖，是另一种执行方式，还没测过。

两个功能**分开测、分开判定**。共同条件：开关打开（日经昨收乖离率 ≤ -5%），股票池为日经 225，往返成本 0.1%，第 5 天止损的规则不变。

**A. 限价卖（只换卖法）**
- 交易集合和基准完全一样：昨天收盘破线、今天开盘买的那些交易。
- 只把卖法换掉：持有期内当天最高价 ≥ 当天目标价就算成交，成交价取 max(目标价, 开盘价)。
- 对照组是现有卖法："收盘到目标 → 下一个开盘卖"，基准约为每笔 +2.34%。

**B. 埋伏限价买（新的买入来源）**
- 交易集合：昨收没破线，但在今天触发价上方 5% 以内的股票（就是推送里会列出来的那些）。
- 当天最低价 ≤ 触发价就算成交，成交价取 min(触发价, 开盘价)。卖法采用 A 的判定结果。
- 对照组是同一天"昨收已破线、开盘买"的交易。

**判定**（我的判断）：
- 每个功能单独判定：平均每笔不比对照组低 0.5 个百分点以上，就保留。
- A 不通过：一手股也改成"昨收到目标 → 开盘市价卖"，并去掉 9:30 的"持仓到价"提醒。
- B 不通过：去掉 7:30 的埋伏价一栏，以及 9:30 的"开盘砸穿"一栏。

回测结果告诉用户，**但不用等用户批准**，按上面的规则直接定下来，接着做。

## 8. 已有的回测结论（供参考）

条件：日经 225 的 223 只、2010~2026 年，可执行方式（昨收信号 → 开盘买 → 开盘卖，最多 5 天），往返成本 0.1%。

| 大盘条件 | 笔数 | 胜率 | 平均每笔 | PF |
|---|---|---|---|---|
| 不看大盘 | 4,873 | 61% | +1.53% | 1.78 |
| 日经 ≤ -5% | 2,741 | 67% | +2.34% | 2.19 |
| 日经 ≤ -10% | 1,011 | 78% | +3.73% | 3.06 |

选股相关的发现：
- 按个股过去成绩选股：2010~17 选、2018~26 检验，秩相关 -0.07，没用。
- 按行业选股：秩相关 +0.03，没用。
- 同一天里，高波动的股票比低波动的稍好，前后两段方向一致。

**局限**：
- 股票池用的是现在的成分股，有幸存者偏差。
- 崩盘档的结果只来自 16 年里 11 个独立事件。
- 单笔最差 -25%。
- 这是历史统计，不是投资建议。

## 9. 约束

- 券商的 ひと株（单元未满股）只能下市价单。8:03 前下单按当天早盘开盘价成交；8:03 到 14:30 之间下单，按当天收盘价成交。
- 日股一手 100 股。东证交易时间：上午 9:00–11:30，下午 12:30–15:30。
- yfinance 的日股数据有约 20 分钟延迟。
